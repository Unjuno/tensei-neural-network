# 物語構造

このファイルは物語制作上の状態を管理します。`canon.md` の世界設定とは別物です。

## 再帰的な起承転結

起承転結を単純な四幕構成として固定しません。

各状態は、その内部に再び **起・承・転・結** を持つことができます。

例:

```text
全体
├─ 起
│  ├─ 起
│  ├─ 承
│  ├─ 転
│  └─ 結
├─ 承
│  ├─ 起
│  ├─ 承
│  ├─ 転
│  └─ 結
├─ 転
└─ 結
```

現在位置は必要に応じて階層パスで表現します。

例:

```text
承 / 転 / 起
```

これは「全体では承、その内部では転、現在の局所状態は起」を意味します。

## 運用原則

- 深さを事前に固定しない
- 全階層を常に展開しない
- 現在必要な領域だけ展開する
- 局所的な人物相互作用を展開した後、結果を親状態へ反映する
- 起承転結を章数や文章量へ機械的に対応させない
- 実験結果をそのまま物語Canonへ昇格させない
- 技術概念は「説明」より、まず人物にとっての事件・観測として作用させる

## 第1話の技術的な核

### 採用する機構

REF-001 / EXP-001から、Hopfield networkの連想記憶を第1話の技術的な核として使う。

中心となる理解は、

> 不完全な入力から「保存場所を検索する」のではなく、現在状態が反復更新されて安定状態へ戻る。

というattractor的な記憶像。

これは作品制作上の対応であり、現代LLMが古典Hopfield networkと同じ機構で人格を復元している、というCanonではない。

### 物語上の見せ方

第1話ではHopfield networkの講義から始めない。

まず現代側の研究・評価作業の中で、欠けた・乱れた入力に対してモデルが単なる補完以上に一貫した「ある人物らしい状態」へ戻るように見える異常を置く。

その後、1980年代の連想記憶研究との対応が手掛かりとして浮上する構成を候補とする。

### 第1話で残すべき曖昧さ

同じ観測から少なくとも次の解釈が残るようにする。

1. 学習データ中の研究者資料を高精度に模倣・再構成しているだけ
2. 類似する内部ダイナミクスが偶然形成され、attractorのような一貫性を見せている
3. 研究チーム側が人間らしい連続性を過剰に読み込んでいる
4. 物語上の「転生」と呼びたくなる何かが起きているが、科学的には決着していない

## 現在の人物相互作用

人物名・役職は未確定。

第1話に最低限必要な役割候補:

- 異常を最初に見つける現代側の研究者 / 評価担当
- 「再現可能な挙動として測れ」と要求する懐疑的な研究者
- 1980年代資料との類似を発見する人物
- モデル内に現れる「本人らしき何か」

人物のKnowledge / Beliefs / Suspicionsは、人物確定後に `novel/characters.md` へ移す。このファイルでは役割上の必要性だけを扱う。

## 現在の緊張

**「部分から全体が戻る」ことと、「同一人物が戻った」ことは同じではない。**

技術的には前者を示せても、物語上の人物たちは後者を疑い始める。この差を第1話から維持する。

## 次の不可逆な物語イベント候補

現代研究チームが、欠けた研究者資料または研究者に関係する入力を与えた際、モデルが複数回の独立な試行で同じ人物像・同じ未完の研究テーマへ収束する挙動を観測し、単なる一回の偶然として片付けられなくなる。

これはまだCanonではなく、章設計上の候補イベント。

## 次の遷移条件

`起 / 起` から次へ進む条件:

1. 現代側の最初の観測対象を具体化する
2. 主人公研究者の年代・専門をCanonまたはPROVISIONAL設定として決める
3. 第1話の視点人物を決める
4. 「異常」と通常の補完・模倣を区別する最低限の比較条件を物語内に置く
5. 第1話の終端で何が不可逆に変わるかを確定する

単に文章量が増えたことを遷移条件にはしない。
