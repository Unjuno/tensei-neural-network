# 物語構造

このファイルは物語制作上の状態を管理します。`canon.md` の世界設定とは別物です。

## 再帰的な起承転結

起承転結を単純な四幕構成として固定しません。各状態は内部に再び起・承・転・結を持つことができます。

```text
全体
├─ 起
│  ├─ 起
│  ├─ 承
│  ├─ 転
│  └─ 結
├─ 承
├─ 転
└─ 結
```

現在位置は必要に応じて `承 / 転 / 起` のような階層パスで表現します。深さを事前に固定せず、必要な領域だけ展開します。

## 運用原則

- 起承転結を章数や文章量へ機械的に対応させない
- 実験結果をそのまま物語Canonへ昇格させない
- 技術概念は説明より、まず人物にとっての事件・観測として作用させる
- 小説と実験は多対多で接続し、1章=1実験に固定しない

## 第1話の技術的な核

### 採用する思考モデル

REF-001 / EXP-001 / EXP-002から、Hopfield networkの連想記憶とattractorを第1話の技術的な入口に使う。

EXP-001から得た第一の理解:

> 不完全な入力から保存場所を検索するというより、現在状態が反復更新されて安定状態へ戻る。

EXP-002から得た第二の理解:

> 安定して収束したことは、意図した原像へ正しく戻ったことを保証しない。

これらは作品制作上の対応であり、現代LLMが古典Hopfield networkと同じ機構で人格を復元しているというCanonではない。

## 第1話で見せる順序

Hopfield networkの講義から始めない。

1. 現代側の研究・評価作業で、欠けた・乱れた研究者関連入力に対してモデルが強く一貫した人物像へ戻るように見える
2. 再試行しても同じ研究テーマ・価値判断・言い回しが現れ、単発の偶然では片付けにくくなる
3. 研究チーム内で「再構成精度が高いだけ」「内部状態のattractor的な安定性では」「人間が連続性を読み込みすぎている」という解釈が分かれる
4. 1980年代の連想記憶研究が、現象を考えるための歴史的手掛かりとして浮上する

技術説明は事件を理解する必要が生じた後に出す。

## 中心の緊張

**「部分から全体が戻る」ことと「同一人物が戻った」ことは同じではない。**

さらにEXP-002を踏まえ、もう一段分ける。

1. 状態が安定している
2. 既知の人物資料と整合する
3. 元の人物の状態を正しく再構成している
4. その人物本人である

物語上の研究者たちは、この4段階のどこまで証拠があるかで対立する。

## 第1話で残すべき解釈

同じ観測から少なくとも次を残す。

- 学習データ中の研究者資料を高精度に模倣・再構成しているだけ
- 類似する内部ダイナミクスが形成され、一貫した状態を生成している
- 研究チーム側が人間らしい連続性を過剰に読み込んでいる
- 一貫しているが原像とは異なる再構成物が成立している
- 物語上は「転生」と呼びたくなる何かが起きているが、科学的には決着していない

## 現在必要な役割

人物名・役職はまだ未確定。

- 異常を最初に見つける現代側の研究者 / 評価担当
- 「再現可能な挙動として測れ」と要求する懐疑的な研究者
- 1980年代資料との類似を発見する人物
- モデル内に現れる「本人らしき何か」

人物のKnowledge / Beliefs / Suspicionsは、人物確定後に `novel/characters.md` へ記録する。

## 次の不可逆な物語イベント候補

現代研究チームが、欠けた研究者資料または研究者に関係する入力を与えた際、モデルが複数回の独立な試行で同じ人物像・同じ未完の研究テーマへ収束する挙動を観測する。

重要なのは「同じ人物らしさが出た」だけではない。通常の補完モデルや対照入力と比べても異常な一貫性があり、研究チームが正式な検証対象として扱わざるを得なくなることを不可逆点とする。

これはまだCanonではなく、章設計上の候補イベント。
