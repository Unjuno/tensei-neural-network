# ペルソナ運用

このディレクトリは、物語内で行動する人物・モデル・主体の**定義と初期条件**を管理します。

目的は、作者やAIが完成した筋書きを各人物へ配ることではありません。各ペルソナが、その時点で知り得る事実・信念・目的・誤解だけから行動し、その相互作用と世界の結果から物語が生じる状態を作ります。

## ペルソナ数は固定しない

現在の5ペルソナは初期集合にすぎません。

物語が進み、新しい人物、モデルinstance、組織的主体、歴史上の人物などが必要になれば、`PER-006`, `PER-007` ... と安定IDを追加します。

一度登場したペルソナは、離脱・死亡・休眠・分岐などでactiveでなくなっても、過去状態を消しません。

## Bootstrapからペルソナを見つける

物語開始時や大きな時代・環境切替時は、`../bootstrap/` のBootstrap Frameを共通の背景として使います。

Bootstrapに含まれる人物・組織・model instanceをすべてペルソナにするわけではありません。次のいずれかを独立して追跡する必要がある主体だけを`PER-xxx`にします。

- 局所的なKnowledge / Beliefsを持つ
- 独立したGoalsや判断を持つ
- 他者と異なる観測境界を持つ
- eventによって状態が変化し、その履歴が後続因果へ影響する

背景上の単なる名前、設備、制度、組織名などは、必要がなければ世界側のentityのまま扱います。

## 定義と状態を分ける

`PER-xxx-*.md` には、比較的安定したものを置きます。

- 識別子
- 役割
- 初期目的
- 初期知識境界
- 初期信念
- 認知スタイルのbaseline
- 盲点
- 初期関係
- 未来知識の禁止範囲

物語が進んだ後の**現在状態**はここへ上書きしません。

時間に依存する Knowledge / Beliefs / Goals / Relations / Memory / 状況等は `../state/personas/` に保存します。

したがって、同じペルソナでも

```text
PER-001 definition
P_001(t0)
P_001(t1)
P_001(t2)
...
```

は別です。

人物そのものの定義と、ある時点での人物状態を混同しません。

## 基本原則

1. **ペルソナは未来のプロットを知らない。**
2. ペルソナは `canon.md` の未観測情報、他者の非公開状態、長期プロット候補を自動的には知らない。
3. ペルソナの発言・記憶・自己認識は、その人物の状態であって客観的事実ではない。
4. ペルソナは「物語を面白くするため」ではなく、自分の目的・価値判断・認知スタイルに従って行動する。
5. 他者の発言や行動を観測した場合、自分の状態を更新できる。ただし誤解したまま更新してもよい。
6. 行動の結果はペルソナ自身が決めず、`../environment.md` の規則と `../state/world.md` の現在世界状態から解決する。
7. モデル内の存在が自分を誰だと名乗っても、その自己申告だけでは本人性をCanonへ昇格させない。
8. ペルソナの状態は時間から独立させない。変化は `../events/` とstory timeから辿れるようにする。
9. 初期化・再初期化は`../bootstrap/`から行い、背景全文を全員へ共有しない。

## ペルソナ状態

各ペルソナ `i` の時点 `t` の可変状態を概念的に次で扱います。

```text
P_i(t) = {K, B, G, C, R, M, X}
```

- `K` (Knowledge): 本人が知っていると扱う情報
- `B` (Beliefs): 信じていること。誤っていてよい
- `G` (Goals): 現在の目的・優先順位
- `C` (Cognitive style): 問題の見方、判断の癖。長期的には変化しうる
- `R` (Relations): 他者への信頼・警戒・利害関係
- `M` (Memory): その人物が保持している物語上の記憶
- `X` (Situational state): 場所、身体、権限、所持情報、現在作業など

実際の時系列履歴は `../state/personas/README.md` の規則に従います。

## 相互作用ループ

1. 対象story timeのBootstrap / event head / state同期を確認する。
2. `state/world.md` と現在event文脈から、そのペルソナが観測可能な情報だけを渡す。
3. ペルソナは現在の `P_i(t)` だけから発言・行動・判断を生成する。
4. 全員の行動と外部変化を `environment.md` の制約でeventとして解決する。
5. 世界状態を更新する。
6. 各ペルソナへ、その人物が実際に観測できた結果だけを返す。
7. 必要なペルソナ状態だけを更新する。
8. 発生したeventを `timeline.md` のstory timeへ結び付ける。
9. 状態遷移を `structure.md` の再帰的な起承転結で整理する。
10. そのログを材料に小説本文を書く。本文は結果の表現であり、結果を先に決める装置ではない。

## 増殖・fork

同じ人物状態、model instance、checkpoint等が物語上で複数へ分かれ、同時に独立した経験を持つようになった場合は、分岐点から別`PER-xxx`にします。

子ペルソナは親のstateを継承できますが、分岐後のKnowledge / Memory / Relations等は別々に更新します。どの親state、story time、event headから分岐したかをstate側へ残します。

## 再初期化

AIセッション変更、モデル交換、長期間の中断等でペルソナを再生成する場合、現在の設定ファイルを寄せ集めて推測し直しません。

対象`BOOT-xxx`、story time、parent event head、対象時点までのworld/persona stateを読み、同じ同期点から再構成します。再初期化によって過去stateを書き換えたり、未観測情報をKnowledgeへ補ったりしません。

## 現在の初期ペルソナ

- `PER-001-modern-evaluator.md` — 現代側の評価担当
- `PER-002-skeptical-researcher.md` — 再現性・反証を要求する研究者
- `PER-003-archive-researcher.md` — 史料・来歴を調べる人物
- `PER-004-model-instance.md` — 現代モデル側に観測される存在
- `PER-005-1980s-researcher.md` — 1980年代の研究者

氏名・所属・年齢などは、現時点で必要なものだけ後から具体化します。人物を細部まで先に固定して物語を閉じない一方、行動が恣意的にならないだけの目的・知識境界・認知スタイルは持たせます。

現代開始時点の実際の同期状態は `../bootstrap/BOOT-001-modern-opening.md` と `../state/personas/` を参照します。PER-005の1980年代時点stateはBOOT-001では初期化しません。
