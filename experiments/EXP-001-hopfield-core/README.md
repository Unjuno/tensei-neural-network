# EXP-001 Hopfield型連想記憶の中核挙動を追試する

## 概要

- 実験ID: `EXP-001`
- 種別: Replication
- 対象: Hopfield (1982) の二状態連想記憶モデルの中核機構
- 関連する問い: `Q-001`
- 関連する仮説: `H-001`
- 原典: `REF-001`
- 補助原典: `REF-002`
- 状態: **実行済み — PASS**

この実験は原典の特定図表や当時のハードウェア条件を完全に再現するものではない。原典の中心的な機構である「対称相互結合・非同期更新・安定状態・content-addressable memory」を、現代の小さなプログラムで再現する **core-mechanism replication** とする。

## 目的

次の3点を同一実装で確認する。

1. 埋め込んだ記憶パターンが安定状態になる
2. 破損したcueから元のパターンへ完全復元できる
3. 非同期1ニューロン更新では計算上のenergyが増加しない

## モデル

状態は `{-1, +1}` の二値表現を用いる。

### 変数

| 変数 | 意味 | 単位 | 定義・範囲 | 型 |
|---|---|---|---|---|
| `N` | ニューロン数 | 無次元 | 100 | int |
| `P` | 保存パターン数 | 無次元 | 3 | int |
| `x_i` | 現在のニューロン状態 | 無次元 | `{-1,+1}` | int |
| `ξ_i^μ` | 記憶パターンμの要素 | 無次元 | `{-1,+1}` | int |
| `w_ij` | ニューロンi,j間の重み | 無次元 | 実数、`w_ii=0` | float |
| `h_i` | local field | 無次元 | `Σ_j w_ij x_j` | float |
| `E(x)` | 計算上のenergy / Lyapunov関数 | 無次元 | 下式 | float |

ここで `E` は物理的エネルギー[J]ではない。状態遷移を記述するための無次元の評価量として扱う。

### 重み

Hebbian outer-product ruleを次で実装する。

```text
w_ij = (1/N) Σ_μ ξ_i^μ ξ_j^μ    (i ≠ j)
w_ii = 0
```

このため `w_ij = w_ji` となる。

### 非同期更新

1回に1ニューロンだけ更新する。

```text
h_i = Σ_j w_ij x_j

h_i > 0 なら x_i ← +1
h_i < 0 なら x_i ← -1
h_i = 0 なら x_i を変更しない
```

各sweepでは全ニューロンを1回ずつ、固定seedから生成したランダム順で更新する。

### Energy

```text
E(x) = -(1/2) Σ_i Σ_j w_ij x_i x_j
```

対称重み・自己結合なしで1ニューロン `i` だけを `x_i → x'_i` と更新すると、

```text
ΔE = -(x'_i - x_i) h_i
```

更新規則は `x'_i` をlocal fieldと同符号に揃えるため、理想的には `ΔE ≤ 0` となる。浮動小数点誤差を考慮し、実装上は `1e-10` を超える増加をenergy increaseとして数える。

### 単位確認

`x_i`, `ξ_i^μ`, `w_ij`, `h_i` はすべて無次元なので、`E` と `ΔE` も無次元である。物理単位[J]へ変換しない。

## データ・入力条件

### 記憶パターン

- `N = 100`
- `P = 3`
- NumPy `default_rng(1982)` から独立に `-1/+1` を生成する
- 生成した3パターン自体を保存対象とする

この固定seedにより同一version系のNumPyで入力を再生成可能にする。

### 破損cue

- 各記憶パターンにつき50 trial
- 総trial数: 150
- 各trialで100 bit中 **正確に20 bit** を重複なしで選んで反転する
- corruption seed: `100000 + pattern_index * 1000 + trial_index`
- update-order seed: `200000 + pattern_index * 1000 + trial_index`

## 実行環境

事前想定:

- Python 3.11以上
- NumPy 1.26以上、3未満
- CPUのみで十分

初回実行:

- Python 3.13.5
- NumPy 2.3.5
- Linux 6.18.35 x86_64 / glibc 2.41

厳密な実行環境は `results/summary.json` を正とする。

## 手順

1. 固定seedから3個の二値パターンを生成する
2. Hebbian ruleで対称重みを構築し、対角成分を0にする
3. 3パターンすべてが更新後も変化しない固定点か確認する
4. 各パターンについて50個の20%破損cueを作る
5. cueごとに非同期更新を実行する
6. 1 sweepで状態変化が0になった時点で停止する
7. 最大50 sweepsで停止する
8. 各trialで最終状態が対象パターンと完全一致したか確認する
9. 全更新過程でenergy増加が発生していないか確認する
10. 集計結果と実行環境を `results/summary.json` に保存する

## 必要サンプル数・試行数

- 3 patterns × 50 trials = **150 trials**

第1追試では統計的な容量推定を目的にしない。複数cueに対して中核挙動が安定して観測されるかを見るための操作的試行数として固定する。

## 停止条件

各trialについて、次のいずれかで停止する。

1. 1 sweep全体でニューロン状態が一度も変わらなかった
2. 50 sweepsに到達した

2の場合、そのtrialは収束未確認として記録する。

## 期待される結果

- 3個の保存パターンがすべて固定点になる
- 20%破損cueの大部分が元パターンへ戻る
- 非同期更新でenergyが増加しない

## 判定対象

**Hopfield (1982) の中核的なcontent-addressable memory挙動を、この事前定義条件の小規模実装で再現できたか。**

## PASS / FAIL / UNCERTAIN 判定基準

### PASS

次をすべて満たす。

1. 保存した3パターンすべてが固定点である
2. 150 trial中のexact recovery率が **95%以上**
3. 全trial・全非同期更新で `ΔE > 1e-10` のenergy increaseが **0回**
4. 全trialが50 sweeps以内に停止する

### FAIL

実行そのものは有効だが、上記PASS条件のいずれかを満たさない。

### UNCERTAIN

以下などにより、事前基準に対する有効な判定ができない。

- 実行エラー
- seed・入力条件・重み定義が事前計画から逸脱した
- 数値計算上の異常が疑われる
- 実行途中でコードまたは判定基準を変更した
- 結果ファイルが不完全

## 原典条件からの主な差異

- `{-1,+1}` 表現を使う
- NumPy上のデジタルシミュレーションである
- 原典の特定図表をそのまま再現しない
- N=100, P=3, 20% bit flip, 95%成功率という操作的基準は本プロジェクトが第1追試用に固定したものであり、原典が同じ数値基準を主張したという意味ではない
- 記憶容量限界、相関パターン、高負荷領域、graded-response neuronはこの実験の対象外

## 既知の限界・不確実性

- 低負荷 `P/N = 0.03` のため、storage capacityは評価できない
- random patternの特定seedに依存する
- exact recoveryのみを成功とし、近い状態への復元を別評価しない
- 初回実行は単一環境であり、独立再現ではない
- 生物学的記憶の妥当性を検証する実験ではない
- PASSしても「人間の記憶がHopfield networkで実装されている」とは言えない
