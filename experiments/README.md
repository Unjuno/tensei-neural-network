# 実験

再現可能な追試・拡張実験を置きます。

実験は「結論」ではなく「証拠」です。結果の解釈は `research/findings.md`、研究として読める整理は `research/reports/` と分離します。

## 小説との分離

**小説を実験レポート風に構成しません。**

小説では、人物がその場で実際に観測したこと、口にした言葉、気づいた違和感、失敗、判断から次の行動が生じます。

その過程で検証可能な問いが生まれた場合にのみ、研究側でQ / H / EXPへ切り出します。

したがって、

- 一話 = 一実験とはしない
- 実験ID順を物語の話数順にしない
- 実験結果を本文へ研究レポート形式で貼り付けない
- 一つの話から複数の派生実験が生まれてよい
- 一つの実験結果が複数の後続場面へ影響してよい

ものとします。

物語内の発言・観測が研究を誘発した場合は、その由来となったeventや言葉を研究レポート側へ記録できます。ただし、それを理由に物語の展開を実験予定へ合わせません。

## 研究レポートとの分離

各実験の再現性正本は `experiments/EXP-xxx-*/` に置きます。

研究としての背景、結果の読み方、限界、派生した問いは `research/reports/EXP-xxx.md` にまとめます。

```text
experiments/EXP-001-.../README.md
        ↓ execution evidence
research/reports/EXP-001.md
        ↓ research interpretation
research/findings.md
```

研究レポートには新しいIDを付けず、対応するEXP IDをそのまま使います。

## 実験IDとディレクトリ名

実験には安定ID `EXP-XXX` を割り当て、ディレクトリ名と一致させます。

```text
EXP-001-perceptron/
EXP-002-hopfield-memory/
```

IDは再利用しません。採番規則は `POLICY.md` に従います。

## 最小構成

```text
EXP-001-example/
├─ README.md
└─ run.py
```

必要な場合だけ `results/`, `requirements.txt`, 設定ファイルなどを追加します。

## 各実験READMEに残す内容

### 実行前に固定する項目

- 実験ID
- 目的
- 判定対象: この実験で何を判定するのか
- 関連する研究上の問い `Q-...`
- 関連する仮説 `H-...`（ある場合）
- 種別: Replication / Extension
- 原典・参考文献 `REF-...`
- 親実験 `EXP-...`（派生実験の場合）
- 物語中の観測から派生した場合、その由来となるevent / 発言 / 観測
- データ・入力条件
- 実行環境
- 手順
- 必要サンプル数、試行数、seed数など。固定しない場合はその理由
- 停止条件
- 期待される結果
- **判定基準**: どの測定値がどの条件を満たしたら PASS / FAIL とするか
- 原条件からの差異

### 実行後に記録する項目

- 観測された結果
- 判定: PASS / FAIL / UNCERTAIN
- 実行前計画からの逸脱
- 既知の限界・不確実性
- raw result / log / outputへの参照（保存する場合）
- 関連するFinding `F-...`（作成した場合）
- 対応する研究レポート `research/reports/EXP-xxx.md`

## 派生実験

別の研究上の問いを検証する場合は、元実験へ継ぎ足さず新しいEXP IDを割り当てます。

特に次は独立実験に分ける候補です。

- 判定対象が変わる
- 新しい失敗モードの内部構造を調べる
- 元実験の事前基準では扱えない操作を導入する
- 物語上の相互作用から新しい検証可能な問いが生じた

同じ判定対象に対する小さな条件変更だけなら、同一実験内の追加runとして扱える場合があります。

派生関係は `Parent experiment` として明示します。

## PASS / FAIL / UNCERTAIN の意味

この判定は、**その実験で実行前に定めた判定対象・判定基準に対する判定**です。仮説が真か偽かを直接表しません。

- `PASS`: 有効な実行結果が、事前に定めたPASS条件を満たした
- `FAIL`: 有効な実行結果が、事前に定めたPASS条件を満たさず、FAILと判断できる
- `UNCERTAIN`: データ不足、実行失敗、条件逸脱、測定誤差、結果の曖昧さなどにより、事前基準に対して有効に判定できない

### Replicationの場合

判定対象は原則として「原典で主張・報告された対象結果を、明示した条件で再現できたか」です。何をもって再現とするかを実行前に数値または観測可能な条件として定めます。

### Extensionの場合

判定対象は、変更した条件の下で事前に定めたテスト条件を満たすかです。関連仮説がある場合、`research/hypotheses.md` に「この実験の判定を仮説状態へどう解釈するか」を実行前に記録します。

## 判定基準を後から変えない

結果を見た後で、元の判定基準を黙って書き換えてはいけません。変更が必要な場合は、元の基準と変更理由を残し、そのrunを探索的結果または `UNCERTAIN` として扱うか、新しい実験として再実行します。

## raw result とREADMEが食い違った場合

保存されたraw result / logとREADMEの要約が食い違った場合、要約だけを都合よく修正して結論を維持してはいけません。実行条件とraw resultを再確認し、解消するまで判定を `UNCERTAIN` として扱います。

## 原則

1. 古典研究は原則として追試から始める
2. 原条件と変更条件を区別する
3. 期待と異なる結果も保存する
4. 実行していない結果を記録しない
5. 別の研究上の問いを検証し始めた場合は別実験に分ける
6. 同じ研究目的で原条件から小さく条件を変える場合は同一実験内でもよい
7. `PASS` を「仮説が真」と読み替えない
8. 小説の話数や展開を実験番号へ従属させない

## 計算環境の目安

古典追試は可能な限り一般的なPCで実行できる軽量な構成を優先します。外部Notebook環境を必須にはしません。
